# Hide Report Issue button for authority roles + voice-to-text + SLA worker refactor

Three independent features landed in three commits touching only their declared files: FEAT-001 guards the `+ Report Issue` entry points from authority roles, FEAT-002 adds browser-native voice input to the report form, FEAT-003 moves the SLA escalation worker from a standalone cron script into an in-process setInterval wired into `server.js`. The role-gating implementation uses `'sub-admin'` and `'super-admin'` string literals, which match the backend's `USER_ROLES` enum exactly. One confirmed structural concern exists in the voice hook's `onresult` handler that creates a double-append on every interim result event.

Watch for: **confirmed** — `useVoiceToText` accumulates the full session transcript on every `onresult` event, then the `useEffect` in `ReportIssue.jsx` appends the whole accumulated string to the description on every update; a single voice session that fires 10 interim events writes the growing transcript 10 times, producing a heavily duplicated description.

**Verdict**: NEEDS_CHANGES

---

## High-level view

FEAT-001's `isAuthority` guard uses `user?.role === 'sub-admin' || user?.role === 'super-admin'`, which matches the backend enum and the `AuthContext` login check exactly. The original user request listed `admin`, `super_admin`, `sub_admin`, `SubAdmin` as roles to block — none of those strings exist in the database, so the guard correctly targets the actual stored role values. MyReports.jsx was pre-existing and already used `isCitizen` to gate the button; the FEAT-001 spec correctly identified no change was needed there.

The voice hook's `transcript` state is the running concatenation of all results in the current recognition session — it resets to `''` on each `start()` call, then grows as `onresult` fires. The `useEffect` in `ReportIssue.jsx` runs on every `transcript` change, each time appending the full accumulated string. In practice this means the first interim result writes "pothole", the second writes "pothole pothole road", the third writes "pothole pothole road pothole road damaged" — the description grows polynomially within a single session. The correct design is either to append only on session end (`onend`) or to replace the in-progress segment rather than append on every interim event.

FEAT-003's refactor is clean. `checkSLABreaches` no longer touches mongoose connection lifecycle; `startSlaWorker` wraps it in a 15-minute interval; `server.js` calls it after `app.listen`. The `require.main` standalone path correctly restores `mongoose.connect/disconnect` for manual runs.

### Voice transcript accumulation produces duplicate text

`useVoiceToText` sets `transcript` to the running concatenation of all `event.results` on every `onresult` call. With `interimResults: true`, `onresult` fires many times per utterance — each time the string grows. The `useEffect` in `ReportIssue.jsx` watches `transcript` and on every change calls `setFormData(prev => ({ ...prev, description: prev.description + ' ' + transcript }))`. So after N interim events, the description contains the full accumulated string N times over.

The intent is clearly to append spoken words once per utterance, not per interim event. Two clean fixes:

**Option A — append only on final results:**
```js
// In useVoiceToText.js onresult handler:
recognition.onresult = (event) => {
  let finalText = '';
  for (let i = event.resultIndex; i < event.results.length; i++) {
    if (event.results[i].isFinal) {
      finalText += event.results[i][0].transcript;
    }
  }
  if (finalText) setTranscript(finalText);
};
// And in ReportIssue.jsx — the useEffect as-is works correctly because
// transcript is only set when a final result arrives.
```

**Option B — track what's already been appended:**
```js
// In ReportIssue.jsx:
const appendedRef = useRef('');
useEffect(() => {
  if (!transcript) return;
  const newPart = transcript.slice(appendedRef.current.length);
  if (!newPart) return;
  appendedRef.current = transcript;
  setFormData(prev => ({ ...prev, description: prev.description ? prev.description + ' ' + newPart : newPart }));
}, [transcript]);
// Reset appendedRef.current = '' when startVoice() is called.
```

Option A is simpler and aligns with standard SpeechRecognition usage; interim results are useful for showing a live preview in a separate element, not for writing to a form field.
