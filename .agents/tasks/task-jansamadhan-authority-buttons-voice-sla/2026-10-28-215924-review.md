# Authority role gating, voice-to-text input, and SLA escalation worker

Three independent features land in four commits. FEAT-001 hides the Report Issue button from authority roles in Navbar and Sidebar. FEAT-002 adds a browser-native SpeechRecognition hook wired into the description textarea on the ReportIssue page. FEAT-003 refactors the SLA escalation cron script into an in-process setInterval worker started by server.js. A follow-up fix commit (b0226b4) tightens the voice hook to emit only final results and prevent double-append.

**Watch for:** The original request listed four role variants (`sub_admin`, `SubAdmin`, `admin`, `super_admin`). The implementation uses `'sub-admin'` and `'super-admin'` — confirmed correct against the backend USER_ROLES enum. No bare `admin` role exists today, but if one is added later the guard will silently miss it (likely gap, worth documenting).

**Verdict**: APPROVED

---

## High-level view

The authority gating in Navbar and Sidebar uses hyphenated role strings (`sub-admin`, `super-admin`) that match the backend USER_ROLES enum exactly (`constants/index.js: ['citizen', 'sub-admin', 'super-admin']`). The underscore and PascalCase variants in the original spec are incorrect legacy strings not present in the data model. The one forward-looking gap: no `admin` role exists today, but if one is added the guard will not cover it without an update.

The voice hook emits only confirmed final results via `isFinal` gating, scoped from `event.resultIndex` to avoid reprocessing prior interim results. The `voiceSupported` gate means the entire mic+language UI is absent on Firefox and Safari. The `useEffect` in ReportIssue.jsx appends each final transcript segment to the description — it will fire once per final result because `transcript` is reset to `''` on every `start()` call, breaking the chain between sessions.

The SLA worker assumes an existing Mongoose connection when called in-process. `server.js` calls `startSlaWorker()` after `app.listen()` inside the same `try` block as `connectDB()`, making the connection ordering structural. The `require.main` standalone path re-adds its own `mongoose.connect/disconnect` chain for manual runs.

MyReports.jsx and Feed.jsx were not touched. The original task mentioned page-level `+ Report Issue` buttons in those files — FEAT-001 explicitly descoped them, but they may still expose the button to authority roles if they exist.

## Role string: spec variants vs. data model

The original task spec passed `['admin', 'super_admin', 'sub_admin', 'SubAdmin']` as the roles to block. The implementation uses `user?.role === 'sub-admin' || user?.role === 'super-admin'`. The backend `constants/index.js` defines `USER_ROLES = ['citizen', 'sub-admin', 'super-admin']` and the User model enforces this enum. The spec variants are incorrect legacy strings — the guard is **confirmed** correct for the current data model.

The residual concern: there is no `admin` role today, but it is a natural addition. The guard will silently miss it. Adding `|| user?.role === 'admin'` is zero-cost insurance.

## Voice hook: double-append

The initial commit accumulated all `event.results` on every `onresult` event, re-processing prior interim results. The fix commit (b0226b4) scopes the loop to `event.resultIndex` and filters to `isFinal` results only. `start()` resets `transcript` to `''`, so the append `useEffect` in ReportIssue.jsx fires once per final phrase per session. **confirmed** post-fix.

## MyReports.jsx / Feed.jsx out of scope

FEAT-001 explicitly scoped the task to Navbar and Sidebar. `git log -- frontend/src/pages/MyReports.jsx frontend/src/pages/Feed.jsx` returns no commits, confirming neither file was touched. Whether page-level buttons in those files exist and need guarding is a separate tracking item.
